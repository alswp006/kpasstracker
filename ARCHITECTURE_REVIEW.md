# Architecture Review
Generated: 2026-09-21T17:53:06.085Z
Score: 66/100

## Summary
The codebase is a well-layered Toss mini-app (pages → components/hooks → lib) with clear separation of storage, policy, calc and copy logic. The main structural problems are duplicated helpers (haptics, storage keys, constants, month-key logic), a stale `contract.ts` that no longer matches the real implementation, and inconsistent conventions (import aliases, quote style, file naming). No hard circular dependencies were found, but `kpassCalc` and `calc/*` are re-exported through several overlapping paths.

- [structure] Layering leaks: the `useInsightInputs` hook exports input-range constants and the `parseIn` validator that components import; a hook that reads `UNSAFE_LocationContext` from react-router is fragile. `PageShell` namespace-imports modules and probes exports via try/catch to accommodate test mocks, which puts test-environment workarounds in production code. Page-specific pieces are split unevenly (`components/home`, `components/insight` while History/Records inline everything). Template/scaffold comment blocks and Korean prose docs dominate many files. `hooks/kpass.tsx` is a `.tsx` file holding a provider plus hooks, and App.tsx passes the provider around routes while RequireSettings is imported but the onboarding route logic is hidden in the truncated section. — Files: src/hooks/useInsightInputs.ts, src/components/PageShell.tsx, src/hooks/kpass.tsx, src/App.tsx / Fix: Move parseIn and range constants to lib (validation/policy). Fix the tests' mocks (shared `mockAnalytics`) instead of defending in PageShell; use `useInRouterContext`/`useLocation` normally. Consider `pages/<name>/` folders with local components for consistency.
- [consistency] Error-handling and validation patterns diverge: SDK calls are guarded by many separate try/catch blocks; storage returns Result objects in writes but swallows errors in loaders, getItem returns null on failure while setItem/removeItem throw (review.ts must wrap them); calc functions accept `unknown` defensively while others take typed args; `calcRefund` in the contract expects (rides, settings) but the real one takes (rides, fare, type). Import order and mixed `Paragraph` imports (Home imports `@toss/tds-mobile` twice) also show weak lint enforcement. `Settings`, `Ride`, `UserSettings` naming overlaps confusingly. Also `SettingsForm` uses `hasError={... != null}` style, while others use `!== null`. — Files: src/lib/storage.ts, src/lib/review.ts, src/lib/calc/refund.ts, src/lib/contract.ts, src/pages/Home.tsx / Fix: Define a small `safe()` helper for SDK/storage calls, make storage.ts helpers consistently non-throwing, and enable ESLint rules (import/no-duplicates, consistent quotes, no-unused-vars) to catch drift.
- [circular_dep] No true cycle exists, but the structure is close to one: writes.ts imports loaders.ts, kpassStore re-exports both, and STORAGE_KEYS cannot be shared with loaders/writes because importing kpassStore would create a cycle (which is likely why the keys are duplicated). Likewise kpassCopy → kpassCalc → calc/* and kpassCalc re-exports calc/*, so `calc/*` should never import from copy or the barrel. — Files: src/lib/kpassStore.ts, src/lib/storage/loaders.ts, src/lib/storage/writes.ts, src/lib/kpassCalc.ts / Fix: Put STORAGE_KEYS in a leaf module (kpassPolicy or storage/keys.ts) and import it from loaders, writes, and the barrel.
